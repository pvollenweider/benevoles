## Conventions du projet

- **`CHANGELOG.md`** : backfiller `[Unreleased]` au fil de l'eau, à chaque PR mergée qui a un impact utilisateur — pas seulement au moment de la release. C'est ce qui a causé le trou de la version 1.11.1 (tag et release GitHub existants, mais aucune section CHANGELOG) et le retard de plusieurs versions sur `SECURITY.md`.
- **`GUIDE_ADMIN.md` / `GUIDE_BENEVOLE.md`** : décrivent uniquement l'état actuel du produit, jamais de langage « depuis la version X, c'est comme ça ». Ce sont aussi les sources de `/doc/admin` et `/doc/benevole` (pages publiques rendues depuis ces mêmes fichiers).
- **Release** : suivre la checklist « Publier une nouvelle version » dans `CONTRIBUTING.md` (CHANGELOG, package.json/package-lock.json, SECURITY.md, FONCTIONNALITES.md, guides, tag + release GitHub).
- **`SECURITY.md`** : sa table de versions supportées est vérifiée en CI (`scripts/check-security-md.mjs`) — la mettre à jour dans le même commit que tout bump de `package.json`.
- **Tests unitaires** : toute nouvelle fonctionnalité ou correction de bug doit avoir son test Vitest — au minimum un test de régression pour un bug, plusieurs cas pour une fonctionnalité. Extraire la logique testable dans une fonction pure d'un module `src/lib/*.ts` plutôt que de la laisser inline dans une route ou un composant quand elle mérite un test (voir `gantt-utils.ts`, `pdf-export-gantt.ts`, `sector-leaders.ts` pour le pattern). S'ajoute à la règle déjà en place : toute nouvelle route API admin doit avoir un test d'isolation cross-tenant (`src/__tests__/security/cross-tenant-isolation.test.ts`).
- **Vidéos** : les rendus (`videos/output`) ne vont jamais dans Git. Après avoir créé ou régénéré une vidéo (`make video ID=…`), ou quand une modification d'interface rend une vidéo obsolète et qu'elle est régénérée, la publier sur `medias.benevol.app` : `make video-publish KUBE_CONTEXT=<contexte> ID=…` pour l'aperçu, puis avec `APPLY=1` seulement après accord du propriétaire (la commande écrit sur le cluster de production). Le contexte kubectl n'est jamais deviné : le demander.
